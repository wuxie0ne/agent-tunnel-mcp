# agent-tunnel：Go 版首版需求

状态：**首版代码与基础验证已完成；完整发布验收未完成**。实际通过、失败和未验证项见 `docs/implementation-status.md`；Quick Tunnel 300 秒同步命令返回结果已发现兼容性冲突，尚未改动原 P0 取舍。计划从零使用 Go 实现，不把旧实现当作迁移清单。

本文优先服务用户个人管理的临时环境：**够用、容易启动、行为可解释，不建设通用远程运维平台**。第 2～3 节包含既有已确认范围，以及本轮按用户授权选定的简化方案；第 7 节说明主要取舍。不再把普通默认值留成需要用户逐项决策的问题。

第 5～6 节记录风险和验收要求，各项实际证据以实施记录为准。第 8 节给出后续顺序；本轮已获无人值守实施/验证授权；未完成的产品取舍仍需讨论。影响已确定范围、改变安全目标或明显增加工程量的问题，仍须回到讨论；其余实现细节由后续简短设计说明解决。

## 1. 产品目标与角色

用户在临时 Linux 环境（如 Docker 容器、共享服务器）运行轻量的**目标侧访问端**，通过 MCP 让自己选用的本地 Agent 操作这个环境。目标环境可能没有 Claude、Codex、Node.js 等完整 Agent 运行环境。常见任务是系统、网络和性能诊断，也可能通过命令进行数据库修复；项目不为 MySQL 等环境开发专用工具。

```text
用户 → 自选本地 Agent → MCP 地址（含短期 token）
                       ├─ Cloudflare Quick Tunnel ──→ 目标侧访问端 → 目标现有命令
                       └─ 自部署公网中转 ───────────→ 目标侧访问端 → 目标现有命令
```

- **本地 Agent**：由用户自行选择和配置。本项目不开发本地 Agent、本地 CLI 网关或本地确认程序；不承诺所有 MCP 客户端都支持审核模式。
- **目标侧访问端**：首版只支持 Linux x86_64，包括该架构的 Linux 容器；不以目标环境开放公网入站管理端口为前提。访问端可能以 root 运行，命令具有其操作系统身份的实际权限。
- **Quick Tunnel**：为目标提供临时 MCP 地址，使用 `cloudflared`。其内部接入和进程管理方式属于实现设计，不把本地 Agent 换成另一套 MCP 工具。
- **自部署公网中转**：用户自行部署一个服务，同时连接多个临时目标。首版允许直接使用公网 IP + HTTP，不要求域名或 HTTPS 证书；其明文传输风险见第 5 节。

两种接入方式对本地 Agent 提供**相同的 MCP 工具和调用语义**，对用户主要区别是 MCP URL。HTTP 与 Quick Tunnel 的传输安全属性不被视为相同。首版主要面向个人管理的临时环境；生产环境接入须重新评估。

## 2. 首版产品行为（P0）

### 2.1 启动、身份与访问期限

- 有效期、执行超时和并发等配置须为有效正值，并在设计给定的资源上限内；非法参数明确报错，不把 0 隐式当作无限制，也不悄悄修正。
- 目标侧启动后给出可供本地 Agent 配置的 MCP URL；URL **可以包含 token**。token 默认有效 2 小时，可通过启动参数调整；从目标侧进程启动时起算，首次连接耗时也计入有效期，重连不重置到期时间。一个 token 可被多个本地 Agent 客户端使用，代表同一权限范围；不建立客户端独立账号或授权。
- 目标可在启动时指定名称；未指定时默认使用主机名，主机名不可用时仍有可辨认的实例 ID。**每次启动生成新的实例 ID**；身份查询至少给出名称、实例 ID、运行模式和 token 到期时间，另外可查询连接状态。
- 首版不提供原进程内续期、token 轮换或远程延长。需要新一轮访问时由用户重新启动，生成新实例和新地址；预计工作较久时在启动参数中设置更长有效期。
- token 到期后拒绝新操作；已经开始的命令继续执行到完成或自身超时。token 到期**不会自动关闭**目标侧访问端进程；本地给出到期提示，等待用户主动停止。已有命令的结果仍可在原调用链路可用时返回，不因此开放新操作。
- 首版不支持从本地 Agent 远程关闭访问端。用户在目标侧主动正常停止访问端；停止接收新操作，并尝试终止受访问端控制的命令及其子进程；不保证清理脱离控制的后代进程。进程崩溃或被强制杀死不承诺相同的清理效果。

### 2.2 两种接入方式与中转注册

- 一次启动选择一种接入方式，不同时开放两条入口。接入失败时明确报错，不展示已就绪的 URL；初次连接等待有界且可由用户停止。
- Quick Tunnel 和自部署中转均应交付可供用户配置的 MCP URL，不能把同一个 URL 背后的目标悄悄换成另一实例。
- 自部署中转可同时接入多个目标。**中转配置一个共享的注册密钥**；目标侧注册时须提供该密钥，不能开放匿名注册。它用于目标接入中转，**与给本地 Agent 的短期 MCP token 分开**。各目标的 MCP 地址/路由和 token 独立；不提供多用户账号体系。
- **同一运行实例**与中转暂时断开后，在同一中转服务进程仍保有注册信息且 token 仍有效时重连，继续使用原 MCP 地址；离线期间对新请求明确返回“目标离线”，**不缓存或排队命令**。访问端重启生成新的实例 ID 和访问地址，不将旧地址指向新实例或其他目标。
- **中转注册信息只保存在内存，不保证跨中转重启恢复地址**。中转重启后，仍在运行且 token 有效的目标可重新注册、获得新路由并输出新 URL；实例 ID 和原到期时间不变。旧 URL 失效且不得误投，不保留地址别名或重定向。中转启动标识/路由标识的设计必须避免重启后意外复用旧地址。
- 共享注册密钥只负责准入；正常重连还须使用首次注册后取得的实例专属随机凭据或等价证明，不能仅凭名称、实例 ID 或共享密钥覆盖已有路由。目标名称允许重复，路由归属按实例区分；冲突拒绝，不静默抢占。首版不建设账号或证书体系。
- token 到期后不为新调用继续重连注册；接入资源可在已有调用收尾后释放。回收后的旧路由不得分配给其他实例，不要求永久保留“已过期”错误页。
- Quick Tunnel 临时地址在接入中断后的变化情况需按实际行为处理；若地址变化，应把新 URL 明确交给用户，不能假装旧地址仍可用。

### 2.3 MCP 工具与执行资源

首版只需要**访问端自身的目标身份/连接状态查询**和**通用命令执行**能力。不自行实现 CPU、内存、磁盘、网络、进程等系统信息采集工具；本地 Agent 在运行模式许可时按需调用目标环境已有的 shell/程序（如诊断系统、网络、数据库所需的工具）。某个命令或 shell 不存在、权限不足时返回清楚的错误。

- 通用命令支持两种非交互形式：**shell 命令字符串**（可使用目标已有 shell 的管道等能力），以及**可执行文件 + 参数列表**（不依赖 shell）。两种形式遵循同一运行模式，调用必须二选一，不能同时提供或都缺失。
- shell 默认使用 `/bin/sh`，可由目标侧启动参数指定其他 shell；缺失时返回错误，不自动安装或切换。直接执行不隐式套 shell：绝对路径按指定路径运行，不带路径的程序名按目标侧实际 `PATH` 查找。
- 默认工作目录为访问端启动时的工作目录，调用可指定绝对目录；不存在或不可访问时不启动。命令继承访问端环境，首版不提供调用级环境变量覆盖、身份切换或持久 shell。每次调用独立执行，上次的 `cd`、变量赋值不影响下次。stdin 从启动起关闭。
- 一次 MCP 调用同步等待命令完成，返回 stdout、stderr、退出状态或启动/执行错误。不支持运行中提供 stdin、交互终端、独立后台任务或事后查询结果。
- 执行默认超时 2 分钟，可通过启动参数调整，不提供调用级超时覆盖；超时从目标侧实际启动命令时计算，不含审核等待。每个目标访问端默认最多同时运行 2 条命令，可通过启动参数调整；超出立即返回“繁忙”，不暗中排队。目标身份/连接状态查询不占命令名额；通过命令采集系统信息仍占名额。
- 目标侧 stdout、stderr **分别最多采集 1 MiB**；单次 MCP 结果默认**合计返回不超过 8 KiB**，调用时可要求提高返回上限，但不能取回未采集的内容。内容预算以 stdout + stderr 的字节计量，不包含结果元数据；最大可请求 **256 KiB**。先各分一半预算，一路不足时将空余让给另一路，返回各路输出前部。采集截断和返回截断应分别可辨识；首版不提供命令完成后的补取能力。输出达到上限不应让仍在运行的命令因管道阻塞。
- 不把工作目录限制宣传为权限隔离。通用命令的实际能力取决于访问端运行身份与目标环境现有工具。

### 2.4 三种互斥运行模式

**启动时必须显式选择一种模式**；未指定时显示权限说明并退出，不默认开放命令。三种模式在两种接入方式下的工具行为一致。

| 模式 | 目标身份/连接状态查询 | 任意通用命令（包括看似只读的诊断命令） |
| --- | --- | --- |
| 全部放行 | 直接放行 | 持有有效 URL/token 即可执行 |
| 审核 | 直接放行 | 通过 MCP 用户确认交互请求本地用户二次确认，同意后执行；确认不可用、拒绝或过期则拒绝执行 |
| 严格 | 直接放行 | **一律拒绝**，即使有人请求确认也不放行 |

- 首版**不做安全命令白名单，也不通过解析任意 shell 命令判断“只读”**。因此严格模式首版只能看访问端自身的目标身份与连接状态，**不能做系统诊断**；以后才考虑动态安全命令范围。
- 审核模式下不能让 Agent 传一个“已批准”参数自我批准，也不能把远端输出当作批准。客户端不支持 MCP 用户确认交互时拒绝命令，**不降级**为全部放行。不承诺服务端能独立证明任意客户端界面上确由真人点击，更不承诺公网 HTTP 能抵御主动中间人伪造批准。
- 用户确认必须对应**本次目标实例和实际要执行的完整请求**，展示名称/实例 ID、命令形式、完整命令或参数、实际工作目录和执行超时；不得只展示摘要而执行隐藏内容。不得把某次同意挪用于其他命令或目标。
- 确认等待固定最多 **60 秒**，与命令执行超时分别计时；等待期间不占命令执行名额，每目标最多同时存在 **8 个待确认请求**，超出返回繁忙。首版不为这些辅助上限增加配置参数。
- 请求确认前先检查凭据、模式、参数和目标状态；批准后，在启动前再次检查 token、实例/连接、停止状态、请求有效性和执行名额。确认过期、拒绝、通道失效且尚未启动，或 token 在等待期间到期，都不执行。批准时执行名额已满则返回繁忙，不排队，不保留批准用于以后。
- 同一 token 的客户端共享执行额度，但不共享某次批准。重连不恢复未完成确认；重新调用需重新审核。具体能力协商与消息绑定方式留给协议设计和真实客户端验证。

### 2.5 断线、超时与结果不确定

- 首版的客户端取消通知只影响尚未启动且取消已被目标侧处理的请求，不作为远程杀进程指令；已启动命令继续执行。取消与启动竞态时以目标实际状态为准，本地未收到结果不能证明没有启动。
- 客户端断线**不立即终止**已启动命令；目标侧继续运行到完成或命令自身超时。token 到期也不打断已开始的命令。目标访问端主动正常停止则清理命令。
- 命令超时后，先请求命令及其子进程正常退出，短暂等待后尝试强制终止仍在运行的进程；如实区分“已确认退出”和“无法确认”，不声称已回滚命令的副作用或清理所有脱离控制的后代进程。
- 请求可能已发送，但确认或结果丢失时，客户端看到的应是**可能已执行、结果未知**，而非执行成功；服务端不自动用新请求重试可能产生副作用的命令。首版不提供后台任务查询或用户发起的任务取消，不能承诺跨故障恰好执行一次。
- 只有明确证据证明未执行时才报告“未执行”。认证/模式/审核拒绝、参数错误、明确离线和繁忙，须与未知结果区分；命令已运行并返回非零退出码，也不是“未执行”。链路完全断开时不能保证未知状态送达客户端，工具说明需提醒：断线或等待超时不证明未执行，也不意味着可以安全重试。
- 仅做目标实例内的轻量重复识别：记录当前待确认/执行的内部请求，以及最近 **256 条**已经结束的请求标识和内容指纹，不保留完整输出。识别到重复时不再次启动，返回重复/冲突说明，不提供结果补取；已结束记录可按数量淘汰。标识归属和绑定方式由设计明确，不能把不同客户端的请求混为一条。
- 该记录不落盘、不跨目标重启恢复，不保证记录淘汰后的防重，也不能阻止 Agent 以新标识重新提交相同命令。服务端与中转不自行重试，重连不重放；不建设通用幂等服务。
- 中转已知目标离线时的新请求直接报告目标离线；不能等目标重连后悄悄执行旧请求。即使目标重连，也不能因重新建立连接而重放命令。未知断链通过有界连接检测识别，不承诺零延迟发现网络故障；已转发但无法确认是否执行的请求按未知处理。

### 2.6 身份、结果与运行信息

- 身份/连接状态查询需要有效 token，不提供匿名目标目录。除第 2.1 节已有字段外，返回接入方式、默认工作目录、执行身份、配置的 shell、执行超时、并发及输出上限、命令历史目录及其写入健康状态等自身信息；不运行外部诊断命令，不返回环境变量全集、注册/重连凭据或其他目标的信息。
- 执行结果使用结构化字段，区分是否启动/是否可确认、正常退出、信号终止、执行超时、启动失败和结果未知；有可靠结果时返回退出码或终止信号，不伪造退出码。错误/超时也可携带已采集的部分输出。
- stdout、stderr 分别标明采集截断与返回截断。需要终止时说明受控进程退出是否已确认，不把退出确认当作副作用回滚或后代全部清理。
- 始终持续读取并丢弃超出采集上限的输出。非文本编码、序列化后整个响应上限和后代持有输出管道的有界处理由设计规定，不允许无限等待或无界占用内存。
- 启动就绪时在目标终端显示名称、实例 ID、运行模式、接入方式、完整 MCP URL 和到期时间。后续普通日志默认脱敏 token、注册密钥和重连凭据，不记录完整命令及输出。另按第 2.7 节保存目标侧命令历史，普通运行日志与命令历史的敏感性和用途不同。

### 2.7 目标侧命令历史（P0）

目标端必须留下本地执行记录，便于个人事后核对“请求了什么、执行结果是什么”。首版采用 **JSONL 追加式文件**，不引入嵌入式数据库；这是命令历史，不是任务恢复、结果补取或防篡改审计系统。

**记录内容与边界**：

- 每条记录包含格式版本、事件时间（带时区）、实例 ID 和内部请求标识。记录命令形式、完整 shell 字符串或可执行文件/参数列表、实际工作目录、运行模式、执行超时，以及本次操作是否通过审核。记录反映服务端收到的确认，不声称证明真人身份。
- 已通过模式/审核、即将启动的命令先写入 **执行意图**；调用收尾时写入 **执行结果**，包含是否成功启动、起止时间/耗时、退出码或信号、超时/清理状态、两路输出采集字节数及截断情况。两条事件通过同一请求标识关联。
- 默认不把 stdout、stderr 正文写入文件，不记录环境变量全集，也不额外记录 MCP token、注册密钥或重连凭据；避免把命令历史扩展成大体积输出归档。启动失败的命令也有结果记录。
- 对认证通过且参数有效的命令请求，审核/模式拒绝、审核过期及繁忙记录为拒绝事件，明确没有启动；不承诺逐条持久记录非法请求、认证失败或身份查询，不建公网访问审计系统。
- 客户端或中转断线后，目标侧仍按实际执行情况写收尾记录；目标本地有记录不代表客户端已经收到结果。用户可在目标端直接查看文件，不增加专用的 MCP 历史查询、结果补取或自动重放工具，也不从文件恢复内存防重记录。

**位置、保留与权限**：

- 默认根目录为访问端启动工作目录下的 `agent-tunnel-logs/`，可通过启动参数指定日志根目录；每次运行写入 `<根目录>/<实例 ID>/commands.jsonl`，启动时显示实际绝对路径。目录无法创建或不可写时明确报错，不偷偷切换目录。
- 创建的实例目录采用仅运行用户可访问的权限，文件默认仅运行用户可读写；不通过 MCP 或 HTTP 暴露日志目录。同一日志根目录下，不同实例使用不同文件，避免并发写同一历史文件。
- 固定按文件大小轮转：单文件目标上限 **10 MiB**，每实例保留最近 **5 个文件（含当前文件）**，删除更早的轮转文件，不加压缩、索引或自动上传。单条记录不得任意截断完整命令，需在设计中设置有界命令请求大小，并明确超限拒绝；轮转阈值不是精确硬配额，可能多出一条有界记录。
- 正常停止不删除剩余历史，新的实例也不清理旧实例目录；跨实例总占用不受“5 个文件”限制，由用户定期清理。容器或临时文件系统销毁仍可能丢失记录；需要保留时将日志根目录指向持久目录或挂载卷，工具不负责向外部备份。

**写入失败与不确定性**：

- 完成执行前的检查和名额分配后，先成功写入并同步执行意图，再启动命令；写入失败则不启动，并返回明确的记录失败错误。不能静默退化为完全不记录的执行方式。
- 命令已经启动后，记录写入失败不代表命令失败或副作用被撤销。继续按原执行规则收尾，在目标终端报告记录错误；原调用仍可返回时分别报告实际命令结果与记录失败状态。停止接受新的命令执行，但保留身份/状态查询及本地停止能力；已在运行的命令不因日志故障自动重试或立即终止。首版修复目录/磁盘问题后由用户重新启动，不增加后台自动修复状态机。
- 执行意图并不证明进程已经启动。崩溃、强制杀死、断电或写入故障可能留下缺少结果的记录，不能据此判定未执行、成功或自动重试。设计需处理尾部不完整行、并发写入及轮转故障，但不承诺任意文件系统故障下零丢失。
- 完整命令可能自行包含密码、SQL 数据或其他敏感信息，首版不尝试解析任意命令并自动脱敏。文件权限也不能阻止同一身份运行的命令、root 或主机管理员读取/修改/删除记录；不声称它能抗恶意篡改。

## 3. 发布形态（P0）

目标侧首版只发布 **Linux x86_64** 两种包；自带版采用归档包，不要求嵌入为单个自解压可执行文件：

| 包 | Quick Tunnel 模式 | 自部署中转模式 |
| --- | --- | --- |
| 自带版 | 附带基于 Cloudflare 官方二进制裁剪压缩的 `cloudflared`；目标无需预装 | 不依赖 `cloudflared` |
| 精简版 | 使用目标环境已有的 `cloudflared`；缺少时明确报错 | 不依赖 `cloudflared` |

两种包都不在运行时自动下载 `cloudflared`。裁剪压缩以方便传播为目标；不承诺删减其功能、指定压缩器或预设压缩率。发布时记录官方原始二进制的版本与校验值，保留相应许可及第三方声明；处理后的实际可用性留待验证。**自部署中转服务**也是首版组成部分，首版发布 Linux x86_64 可执行文件与最小运行说明；不把目标侧的“两种包”误称为中转服务的全部发布物。

- 精简版为独立 Go 可执行文件；自带版为该文件与处理后的 `cloudflared` 的归档包。列出最低系统要求、动态运行库依赖、所需出站连接和 Quick Tunnel 执行条件；发布记录包含项目版本、制品校验值、原始/处理后 `cloudflared` 校验值及处理方法。
- 首版不额外交付多架构、容器镜像、服务管理模板、自动安装脚本或自动更新。运行时不引入数据库、Node.js、Python 等项目自身所需的外部运行环境；使用目标现有 shell/诊断程序和 `cloudflared` 的边界不变。
- 中转通过启动配置读取共享注册密钥；目标通过专用环境变量提供注册密钥，避免要求写进命令行或 URL。具体变量名留给设计，示例只用占位值，不提交真实凭据。命令仍拥有访问端身份的实际权限，不把凭据输入方式宣传为对任意命令的隔离。
- 如果处理后的 `cloudflared` 无法通过真实功能验收，先报告体积、兼容性证据，再讨论是否改用原始二进制，不静默改变发布要求。

## 4. 明确不做与以后再考虑（P1）

- 暂不提供 MySQL 等专用工具、自实现的系统指标采集工具、文件传输、端口转发、多用户独立授权或无人值守批量调度。
- 独立任务和后台运行、增量输出、断线后查询/补取、用户取消、stdin、交互式终端及终端尺寸变化留到未来；首版的“同步命令”不暗示支持这些能力。
- 动态安全命令白名单，以及严格模式下更多诊断能力留到未来。
- 不做 token 原地续期、跨中转重启地址恢复、持久任务/结果数据库、单文件自解压或通用幂等/审计平台。目标侧本地命令历史属于 P0，但不因此引入数据库或任务查询。
- 不承诺生产级访问控制、沙箱隔离、跨崩溃恢复、跨故障恰好执行一次或适用于生产环境。实际权限由目标侧运行身份决定。

## 5. 已知风险和待实现设计边界

以下不是等待用户逐条选择的产品功能；在开发设计时需明确处理，并在发布前留下对应的验证结果，历史上这些项目尚未验证；当前逐项状态见实施记录，不能把局部通过解释为全部通过。

1. **公网 HTTP 风险（用户已接受首版取舍）**：自部署中转首版可直接以 `http://公网IP:端口` 暴露服务，不要求域名和证书。无 TLS 的公网通信可能暴露或允许沿途篡改 URL/token、目标注册密钥（若目标侧注册链路也未保护）、命令、批准和结果；截获的有效凭据可能被冒用。短期 token、注册密钥和审核模式都不能单独提供保密性或抵御主动链路攻击。明确区分 Quick Tunnel 和 HTTP 中转的信任边界，不宣称中转不可见内容或具有端到端加密。
2. **MCP 客户端与接入链路兼容性**：实际客户端能否使用含 token 的远程 URL、公网 IP + HTTP、MCP 用户确认交互，以及 Quick Tunnel 能否承载完整审核流程，不能从文档推定。同步的默认 2 分钟命令及可调长命令还要核对实际链路的请求时限；若有冲突，回到产品需求讨论，不暗改超时、审核语义或接入模式。
3. **注册和路由归属**：共享注册密钥如何配置和传给目标、注册冲突如何处理、同一实例重连如何证明身份、离线/过期路由何时回收，应使多目标相互隔离；未完成设计前不声称公网中转能阻止有密钥者冒用其他目标或抵御 HTTP 路径上的攻击。
4. **确认与执行边界**：批准应绑定完整请求和实例；确认消息绑定、重复识别记录淘汰、结果丢失后如何表达未知、token/离线/超时的同时到达如何判定，都需要设计和竞态测试。首版不引入可事后查询的异步任务；不要用这种能力作为解决竞态的默认前提。
5. **环境与资源边界**：容器中的 shell/诊断命令可能缺失或被权限限制；命令输出需有界且避免管道阻塞。进程终止对主动退出可尽力处理，不保证清理脱离控制的后代。返回内容上限已定为 256 KiB；整个响应上限、进程清理等待时间、连接检测时限和中转容量在设计中给出保守有界值。个人使用不要求容量压测或通用限流系统，但不能放任无界资源占用。
6. **命令历史风险**：完整命令本身可能含敏感信息，本地文件权限不提供防篡改或对执行身份的隔离。默认每实例轮转会淘汰旧记录，旧实例目录需用户清理；临时环境销毁可能丢失日志。持久历史仅用于人工核对，不提升跨故障执行保证。启动前写入与进程启动不是原子事务，缺少结果的意图记录必须按不确定处理。

## 6. 后续验证清单（本轮不执行）

- 在两种接入方式下检查相同的 MCP 工具和模式规则；自部署中转额外检查共享密钥拒绝匿名注册、不同目标的地址/token 隔离、同实例重连保留地址、离线立即拒绝且不排队、重启后旧地址不误投。
- 至少选取一个支持 MCP 用户确认交互的客户端，**分别经 Quick Tunnel 和自部署中转**完成“请求命令 → 本地用户确认 → 远端执行 → 返回结果”；还要覆盖拒绝、确认不可用和未经确认时无命令副作用。只证明连通不算完成审核模式验收；此测试客户端不限制用户最终的选择。
- 验证 shell 与直接执行、容器缺失 shell、root 权限、默认/自定义超时、并发上限、双重输出截断及其结果标识；确认有效和过期 token、新操作与已在运行命令的区别。
- 人为制造客户端断线、中转断线、命令执行与结果返回之间断线，以及到期、重连、主动停止的竞态；核对实际执行次数和用户可见的未知结果，不能声称测试之外的恰好一次保证。
- 补充检查取消与启动、批准与到期/繁忙竞态；中转重启重新注册并输出新 URL、旧地址不误投；重连归属冲突；重复请求不再次启动及记录淘汰的保障边界。
- 检查关闭 stdin、独立工作目录/环境、8 个待确认上限、256 KiB 返回预算和两路分配、非文本输出、后代持有管道以及日志脱敏；不以这些检查扩展为生产审计或性能工程。
- 验证命令历史的意图/结果关联、启动失败、拒绝事件、断线后收尾、输出正文不落盘、敏感字段与文件权限、不同实例文件隔离、轮转和保留；检查不可写目录、磁盘写入/同步失败、执行后记录失败、不完整尾行和缺少结果事件，确保不把日志错误解释为未执行或自动重试。
- 自带版和精简版分别验证真实 Quick Tunnel 与 MCP 请求；二进制裁剪后不能只运行 `--version` 就视为通过。单独记录公网 IP + HTTP 的客户端兼容性及其未加密风险；不把功能通过解释成通信安全审计。

通过文档或静态检查不等于上述运行验证通过。若验收暴露首版需求之间的冲突，再与用户确认取舍，不私自缩减已确认范围。

## 7. 个人使用的首版取舍

以下为本轮依据“个人使用、不过度设计”选定的方案，已合并到前文；不再保留为需要逐项选择的悬而未决问题。选定产品方案不代表技术可行性已经验证。

| 项目 | 选择及理由 |
| --- | --- |
| D1 运行模式 | 显式选择。多写一个启动参数比无意开放任意命令更合适，不增加配置向导 |
| D2 执行环境 | `/bin/sh` + 可选绝对工作目录 + 每次独立进程，继承环境，不做持久会话 |
| D3 审核 | 固定 60 秒、8 个待确认请求，批准后再检查；保留必要边界，不开发自己的确认界面 |
| D4 取消与防重 | 不远程杀已启动命令；仅内存记录在途及最近 256 条结束请求，不存输出、不做持久恢复 |
| D5 输出 | 默认 8 KiB，最多 256 KiB，保留各路 1 MiB 采集上限；限制单次响应，不扩展输出补取 |
| D6 有效期 | 从进程启动起算，重连不延期，到期后重启；相比首次 URL 就绪起算，少一个生命周期状态 |
| D7 中转重启 | 不持久化路由，重新注册后显示新 URL；个人使用接受重新配置入口，不维护旧地址别名 |
| D8 发布 | 自带版归档包、精简版独立二进制、中转 x86_64 二进制；暂不做自解压、镜像或自动部署 |
| D9 命令历史 | 目标本地 JSONL，记录完整命令与结果元数据，默认不存输出正文；10 MiB × 5 文件/实例，不用嵌入式数据库 |

通常的字段名、连接检测/退避、清理等待时间、保守资源上限和配置格式，在简短设计说明中直接给出合理值，无需反复询问用户。只有以下情况需要重新讨论：

1. 真实客户端/接入链路无法完成审核，必须新增本地组件或改变批准语义。
2. 同步长命令无法满足要求，必须改超时或引入异步、补取。
3. `cloudflared` 处理后的实际兼容性不满足已定发布要求。
4. 用户需要端到端加密、跨故障恢复、地址长期不变、账号体系或生产隔离等新的安全/产品目标。

这些冲突不能靠静默删减 P0、弱化审核或声称已有安全保障来解决。
